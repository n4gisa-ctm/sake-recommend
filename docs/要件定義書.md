# 要件定義書 — さけAIソムリエ（sake-recommend）

最終更新: 2026-09-14

## 1. プロダクト概要

| 項目 | 内容 |
|---|---|
| プロダクト名 | さけAIソムリエ |
| 一言で | 日本酒に興味が出てきた20代後半の男性に、AIチャットでおすすめの一本を提案するWebアプリ |
| 形態 | SPA（React + Vite + Tailwind CSS）。バックエンドは持たず、Dify のチャットボットAPIを直接呼び出す |
| 参考演出 | [Word Cascade](https://river.tango-gacha.com/) — 単語がまるごと滝のように降ってくる演出 |

## 2. ターゲットユーザーと課題

### ペルソナ

- 20代後半・男性。社会人になって飲み会や外食で日本酒を飲む機会が増え、「日本酒って美味いかも」と思い始めた。
- 銘柄の知識はほぼゼロ。「獺祭」「久保田」など有名どころの名前を聞いたことがある程度。
- 居酒屋のメニューや酒屋の棚を前にすると、何を選べばいいか分からず結局ビールにしてしまう。

### 解決したい課題

1. **選べない**: 好み・シーン・予算を伝えるだけで、具体的な銘柄を提案してほしい。
2. **知らない**: 銘柄名に触れる機会が少ない。→ 銘柄名が降ってくる演出で「あっ、この日本酒聞いたことある！」という気づき・興味の入口をつくる。
3. **聞けない**: 店員に「初心者なんですが…」と聞くのは気恥ずかしい。→ AIになら気軽に何でも聞ける。

## 3. 機能要件

### 3.1 銘柄カスケード演出（本アプリの核となる演出）

- 実在の有名日本酒の**銘柄名（単語まるごと）**が画面上部から下へ流れ落ちる。1文字ずつのマトリックス風ではなく、Word Cascade のように「読める単語」が降る。
- 全画面（ウェルカム／チャット）の背景として常時表示。チャットの可読性を妨げない透明度に抑える。
- **降ってくる銘柄はタップ/クリック可能**（チャット画面）。タップすると「〇〇ってどんな日本酒？」がチャットに送信され、興味の入口として機能する。
- 銘柄プールは全国の知名度が高い銘柄を中心に約70種を内蔵（獺祭・十四代・而今・新政・久保田 など）。
- `prefers-reduced-motion` 環境ではアニメーションを停止する。

### 3.2 チャット（レコメンドの本体）

- Dify チャットボットAPI（`/chat-messages`）と連携。SSEストリーミング表示、非ストリーミングへのフォールバックあり。
- 会話は `conversation_id` で継続。「新しい会話」でリセット可能。
- 初回表示時にターゲットに合わせたサジェスト（クイック質問）を4件表示する。
  - 例:「日本酒初心者。まず何から飲めばいい？」「居酒屋で通っぽく頼める一本は？」「獺祭って何がすごいの？」「焼き鳥に合う日本酒を教えて」
- 送信中は入力を無効化し、タイピングインジケータを表示。
- エラー時は日本語のわかりやすいメッセージを表示し、再試行を促す。

### 3.3 Dify 接続設定

- **優先順位1（推奨）**: ビルド時の環境変数 `VITE_DIFY_API_URL` / `VITE_DIFY_API_KEY` を使用。設定済みならユーザーには設定画面を一切見せず、即チャットを開始できる。
- **優先順位2（フォールバック）**: 環境変数がない場合のみ設定画面を表示し、ブラウザの localStorage に保存する（従来動作）。
- 注意: フロントエンドから直接呼ぶ構成のため、APIキーは閲覧者に露出しうる。公開運用時は Dify 側でレート制限を設定するか、将来的にプロキシ（サーバレス関数）を挟むことを推奨（将来課題）。

### 3.4 銘柄カード（購入への橋渡し）

- AIの返答に登場する**既知の実在銘柄**（内蔵データ約75種）を自動検出し、返答の下にカード表示する。
- カードには味覚タグ（例: 甘口・やや淡麗）、Amazon / 楽天の検索リンク、マイ酒ログへの記録ボタン（気になる / 美味かった / イマイチ）を置く。
- 既知銘柄のみカード化することで、AIが創作した架空銘柄への導線を作らない。

### 3.5 マイ酒ログ（パーソナライズ）

- 銘柄ごとに「気になる / 美味かった / イマイチ」を記録できる（localStorage保存・ブラウザ内のみ）。
- ヘッダーのログボタン（件数バッジ付き）から一覧パネルを開き、記録の確認・削除・購入リンク参照ができる。
- 記録があると、AIへの質問に好みの傾向（美味しかった銘柄など）を**自動で添えて送信**し、レコメンド精度を高める。画面上のメッセージには表示しない。

### 3.6 味覚マップ

- マイ酒ログの銘柄を「甘辛（辛口⇄甘口）×濃淡（淡麗⇄濃醇）」の2軸チャートにプロットする（SVG）。
- 「美味かった」が2件以上あれば、その重心を「あなたの好みゾーン」として表示する。
- 味覚座標は銘柄データ（`src/data/sakeNames.ts`）に内蔵した一般的傾向のおおよその値を使う。

### 3.7 画面構成

| 画面 | 役割 |
|---|---|
| ウェルカム | 世界観の提示（銘柄カスケード＋キャッチコピー）。CTA「日本酒を探してみる」でチャットへ |
| 設定（フォールバック時のみ） | Dify API URL / キーの入力 |
| チャット | メッセージ一覧・サジェスト・入力欄・設定メニュー（新しい会話／設定変更） |

## 4. 非機能要件

- **対応環境**: スマホ（375px〜）〜デスクトップのレスポンシブ。モダンブラウザ（Chrome / Safari / Edge / Firefox 最新）。
- **パフォーマンス**: カスケードはCSSアニメーションのみで実装し、JSによる毎フレーム処理を行わない。表示単語数は画面幅に応じて調整。
- **アクセシビリティ**: 装飾アニメーションは `aria-hidden`。コントラストは本文テキストで WCAG AA 相当を目安とする。`prefers-reduced-motion` 対応。
- **セキュリティ/プライバシー**: 入力されたAPIキーは localStorage のみに保存し、外部送信しない（Dify APIへの認証を除く）。

## 5. スコープ外（今回はやらない）

- ユーザー登録・ログイン、会話履歴の永続化（Supabase連携は現状未使用のため依存関係から削除）
- 銘柄データベース・ECリンク・在庫情報
- Difyワークフロー自体の作成・チューニング（Dify側はユーザー管理）

## 6. 技術構成

- React 18 / TypeScript / Vite 5 / Tailwind CSS 3 / lucide-react
- デプロイ想定: 静的ホスティング（Netlify / Vercel / Bolt Hosting など）
- ディレクトリ: `src/components`（UI）、`src/lib`（Dify・storage）、`src/data`（銘柄プール）、`docs`（本書・デザインガイドライン）

## 7. 受け入れ基準

1. `npm run build` と `npm run typecheck` が成功する。
2. 銘柄名（単語まるごと）が背景に降り、チャット画面でタップすると該当銘柄の質問が送信される。
3. `.env` に Dify 情報を設定してビルドすると、設定画面を経由せずチャットが開始できる。
4. Dify 未設定でも従来どおり設定画面から接続できる。
5. スマホ幅（375px）でレイアウトが崩れない。
